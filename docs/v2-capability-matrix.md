# V2 需求能力覆盖矩阵

本文按《需求分析报告 V2》核对当前前端和 `eventmesh-dashboard-console` 的实际能力。原则是：页面只展示后端或数据库已经提供的数据；后端尚未形成可用闭环的能力不使用模拟数据代替，也不修改后端代码。

## 已完成

| V2 能力 | 前端交付 | 数据来源 |
| --- | --- | --- |
| 登录、会话恢复、注销 | 登录页、401 刷新、原地址返回、退出 | `/auth/login`、`/auth/refresh`、`/auth/me`、`/auth/logout` |
| 组织隔离与角色权限 | 组织切换、系统管理员/组织拥有者/组织管理员/组织成员权限、无权限页面 | 鉴权与组织接口 |
| 工作台 | 集群、Runtime、Topic、消费组、当前连接和最近操作汇总 | 集群及资源查询接口、MySQL |
| 集群列表 | EventMesh JVM、逻辑 EventMesh、RocketMQ、Kafka 查询；名称、类型和状态筛选；架构与管理方式展示 | `queryClusterByOrganizationIdAndType` |
| 基础集群接入 | 创建集群记录、选择集群类型和管理方式 | `activeCreate/createCluster` |
| 集群详情 | 基本信息、Runtime、Topic/消费组/连接数量、最近操作、资源快捷入口 | 集群、Runtime、消息资源、连接和日志接口 |
| 集群资源拓扑 | 全局—组件—实例三级视图、动态方向箭头、整卡下钻、Runtime/连接/Topic/消费组节点详情、搜索和可分享 URL | `queryTreeByClusterId`、`cluster_relationship`、Runtime、连接与消息资源记录 |
| Topic | 跨集群查询、搜索、筛选、分页和创建 | Topic 查询/创建接口 |
| 消费组 | 跨集群查询、搜索、筛选、分页和删除 | Group 查询/删除接口 |
| 客户端连接 | 客户端到 Runtime 的连接清单、搜索和集群筛选 | `/netConnection`、`net_connection` |
| 健康监控 | 集群健康摘要、集群/Runtime 最近 24 小时检查历史 | Health 接口、`health_check_result` |
| 配置查看 | 集群配置查询、搜索、敏感值遮蔽 | `user/config/queryByInstanceId`、`config` |
| 操作审计 | 跨集群操作记录、搜索、筛选和分页 | `cluster/log/getList`、`operation_log` |
| 组织成员 | 成员查询、添加、角色调整和移除 | 组织成员接口 |

## 部分完成

| V2 能力 | 当前范围 | 尚缺的后端闭环 |
| --- | --- | --- |
| 多类拓扑 | 已完成集群资源拓扑；集群列表可显示正向依赖和反向被依赖关系 | 独立影响拓扑、网络拓扑和 Topic 数据拓扑缺少统一聚合接口及关系字段 |
| 集群创建与接入 | 只创建数据库中的基础集群记录，并保存托管方向 | 地址发现、预检、脚本部署、模式化节点编排、异步任务和回滚尚未形成可查询任务闭环 |
| 监控 | 使用已存储健康检查和 Runtime 数据 | CPU、内存、吞吐、Lag、历史趋势和告警缺少稳定的指标契约 |
| 权限治理 | 已完成组织级 RBAC | RAM 资源策略和中间件 ACL 缺少可用查询/写入闭环 |
| 配置 | 已完成只读查询和敏感字段遮蔽 | 当前更新处理器只返回 `success`，不会应用修改，因此未开放编辑 |
| 消息资源 | Topic 支持查询/创建，消费组支持查询/删除 | Topic 删除当前定义为 GET 请求体，浏览器端不可靠；Topic 详情、消息查询、测试生产消费、Offset/Lag 与 Offset 重置缺少稳定接口 |

## 暂缓开发

| V2 模块 | 暂缓原因 |
| --- | --- |
| Connector 目录、实例和 Connection Pipeline | `ConnectionController` 依赖的数据服务当前没有完成注入，接口无法作为稳定数据源 |
| 部署中心与任务中心 | 后端存在部分创建动作，但没有满足任务列表、步骤、日志、状态、重试和回滚的完整查询契约 |
| ACL 管理 | 当前 ACL 查询处理器没有返回可展示的数据 |
| 指标趋势、链路监控、告警和通知 | 没有可用的时序指标、聚合和告警接口；前端不会生成模拟曲线或告警 |
| 元数据同步详情、导入导出、备份恢复 | 缺少稳定且可审计的前端契约 |
| Kafka ZooKeeper → KRaft 迁移 | 缺少迁移计划、阶段状态、校验和回滚接口 |
| 集群复制、完整脚本部署、地址发现与拓扑编排 | 缺少可追踪的异步任务和结果查询闭环 |

## 验收规则

1. 页面数据只来自 EventMesh Dashboard API 与其 MySQL 数据库。
2. 后端成功返回空列表时显示真实空状态；接口失败时显示明确错误或“部分可用”。
3. CPU、内存、吞吐、Lag、趋势和告警等缺少接口的数据不推算、不随机生成。
4. 所有写操作都受前端角色权限约束；真正的数据安全仍由后端鉴权与组织校验负责。
5. 后端能力补齐后，可按“暂缓开发”表逐项开放页面，不需要替换现有真实数据层。
