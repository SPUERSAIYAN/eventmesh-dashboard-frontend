### 1.1 参数位置

- `Body`：JSON 请求体，对应 Controller 中的 `@RequestBody`。
- `Query`：URL 查询参数，例如 `?connectorId=1`。
- `Form/Query`：Controller 未声明 `@RequestBody`，Spring 按表单或查询参数绑定对象。
- `ANY`：使用了未限定 HTTP Method 的 `@RequestMapping`。

### 1.2 返回值

文档中的“返回类型”指 Controller 方法声明的 Java 类型。项目引入了 `decoration-core`，并启用了统一返回与分页装饰，因此实际 HTTP JSON 可能在业务数据外再包装一层。联调时以运行中的 OpenAPI 文档和实际响应为准。

## 12. 已知问题与对接建议

1. 当前至少有 9 个路由存在空实现、返回 `null` 或硬编码结果，已在各表中使用 ⚠️ 标注。
2. `/user/cluster/queryHomeClusterData` 和 `/user/topic/deleteTopic` 使用 GET Body，部分 HTTP 客户端、代理和网关可能丢弃 Body。
3. `deleteTopic` 使用 GET 执行删除，不建议被缓存、预取或直接暴露给浏览器链接。
4. `/report/**` 没有限定 HTTP Method，客户端建议统一按 POST 调用。
5. 多个写操作返回 `void`，客户端不能仅依赖业务返回值判断结果，应同时处理 HTTP 状态和统一响应包装。
6. 接口暂无统一版本前缀，且路径风格混用 `/user`、`/organization`、`/cluster` 和无领域前缀形式。
